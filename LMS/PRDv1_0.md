## 1. Executive summary

Gracified LMS is a multi-tenant learning management platform covering the complete teaching lifecycle: onboarding, school and classroom administration, curriculum delivery, live lessons, assessments, payments, marketing, analytics, and AI-assisted authoring — on web and mobile.

The platform serves two seller types — **institutional schools** (School Admins + Teachers) and **independent tutors** (Personal Teachers) — and one buyer type: **students**, who discover or receive class links, enroll, pay where required, learn from topics, join live sessions, submit work, and receive results.

The product is already substantially built. This PRD describes what exists today (verified against source), what remains to be built, and the requirements that govern both.

## 2. Problem statement

Teachers and schools juggle multiple disconnected tools to run a class: scheduling, content delivery, live calls, assessments, payments, and communication. This results in:

- **Fragmented workflows** — content, payments, and collaboration live in separate tools.
- **Lost revenue** — independent tutors lack a simple way to monetize classes (per-lecture, per-topic, weekly, monthly, one-time).
- **No audit trail** — schools cannot reliably track who paid, what was paid for, and enrollment status.
- **High authoring effort** — creating syllabi, topics, assignments, and exams is manual and time-consuming.
- **Poor reach** — small providers cannot afford marketing infrastructure to grow their student base.
- **External examiner/marker friction** — schools need to share answer scripts with external markers securely, without exposing full accounts.

### Opportunity

A single workspace that unifies classroom management, monetization, live delivery, assessment, external grading, and growth tools — with an AI assistant to reduce authoring effort — replaces the tool sprawl for both schools and independent tutors.

### 3.1 Goals

| # | Goal | Status |
|---|---|---|
| G1 | Make it simple for a teacher to create and run a class from one workspace | Built (web + mobile) |
| G2 | Give students a reliable, accessible learning experience on web and mobile | Built |

### 3.2 Non-goals (v1.x)

- Multi-language support.
- Full offline-first mobile experience (network-error + retry states exist).
- Content marketplace / institution-to-institution sharing.
- Self-hosted or on-prem deployments.
- Native iOS/Android outside Expo/React Native.
- Student self-serve refunds (admin/root-admin only today).

## 7. Current feature inventory (verified against source)

### 7.1 Authentication & onboarding
- Register paths: Student, School Admin, Personal Teacher. Teachers under a school are **invited** (tokenized link → `/set-password`).
- Email verification via token/OTP; unverified users blocked by `auth` middleware (root_admin exempt) and redirected on both web and mobile.
- Forgot password (request → OTP/token → reset). Change password (requires current password).
- 2FA: `POST /api/auth/generate-otp` (6-digit OTP, 5-min expiry + 10 backup codes), `POST /api/auth/verify-otp`; `twoFAEnabled` defaults **on** for root_admin; `tempLoginToken` supports staged login.
- JWT sessions; mobile persists token in AsyncStorage and hydrates via `GET /api/auth/me`.
- Profile/logo upload (`POST /api/auth/upload-logo`, Cloudinary w/ local fallback, 2 MB).
- Subscription gate: `subscriptionCheck`/`enforceSubscription` middleware; `pay_as_you_go` exempt; global kill-switch `Settings.subscriptionCheckingEnabled`.

### 7.2 Schools & multi-school administration
- School CRUD (`name`, `logoUrl`, `shortCode`, SEO `slug`); root/school admins; School Admin can belong to **multiple schools** (school switcher on web).
- Teacher invites: single (`POST /api/users`) and **CSV bulk invite** (`POST /api/users/bulk-invite`, 5 MB).
- Public school page `/s/:identifier`.

### 7.3 Classrooms
- Classroom fields: name, description, learningOutcomes, subject, level (Pre-Primary → Postgraduate → Professional → Vocational → Other), teacherId, schoolId[], students[], schedule[] (dayOfWeek + start/end), capacity (default 30), pricing {type: per_lecture/per_topic/weekly/monthly/one_time/free, amount}, isPaid, classFormat, publicAccess, published, isPrivate, currentTopicId, introVideo, whiteboardUrl/whiteboardActiveAt, shortCode + slug.
- Publication lifecycle: `POST /api/classrooms/:id/publish` and `/unpublish` (idempotent; sends `class_published` notifications).
- Enrollment: `POST /api/classrooms/:id/enroll` (self) with subscription rules applied.
- Share links: `/c/:shortCode`, slug-based `/c/:slug`.

### 7.4 Public lectures & seminars (classFormat: public_lecture / public_seminar)
- `publicAccess` config: `allowGuestAccess` (guest access always enabled for public formats), duration window (`startsAt`/`endsAt`, duration days/weeks), `recordingUrl` (YouTube/Vimeo), `joinInstructions`.
- Public catalog: `GET /api/classrooms/catalog` (public) with search + filters (format, subject, price, free/paid).
- Public classroom page: share modal (QR, WhatsApp/Facebook/X), **Guest Join** (name + email → live join or recording watch; Paystack checkout when paid) → records **PublicAttendee** (`status`: pending_payment/admitted/watched_recording; `accessType`: live/recording).
- Web UI badges: "Live Now" (polls catalog), "Recording", "Window Closed".
- PublicClasses management page (staff) with "Decommission Public Class?" purge confirmation.

### 7.5 Topics & curriculum progression
- Topic fields: name, description, lessonsOutline, order, materials[] (video/document/link/text), recordedVideos[] (file or URL, label, order), isPaid/price, duration {mode: day/week/month/year/not_sure, value}, status (pending/active/completed), startedAt/completedAt/expectedEndDate, nextTopicId, completedBy.
- Progression engine: `POST /api/topics/:id/activate`, `/complete`, `PUT /:id/set-next`, `POST /:id/reset`, `PUT /topics/reorder`, `POST /topics/bulk-create/:classroomId`; daily midnight cron `checkAutoProgression()` advances overdue active topics.
- **Video management:** `POST /:id/upload-video` (Cloudinary/local, 500 MB), `POST /:id/add-video-url`, `DELETE /:id/videos/:videoId`, label + reorder endpoints.
- **Student progress tracking:** `TopicProgress` model — `GET/POST /api/topics/:id/progress` records watchedVideoIds, completionPercentage, lastActiveVideoId (unique per user+topic).
- Topic management timeline UI `/classrooms/:id/manage-topics`.

### 7.6 Assignments
- Types: **MCQ** (correctOption stored, `publishResultsAt` controls release) and **theory** (per-question `markingPreference: 'ai' | 'manual'`).
- CRUD + publish/unpublish, classroom/topic link, dueDate, maxScore.
- Submissions embedded in Assignment: answers (text or selected options), files[], questionScores[], score, feedback, status (`submitted` → `graded` → `returned`).
- Grading: `PUT /api/assignments/:id/grade` (MCQ), `PUT /:id/grade-theory` (manual or AI), `GET /:id/results`, `POST /:id/notify` (reminder).
- Notifications on create, submission (`new_submission`), and grading (`assignment_graded`) via email + push + in-app.

### 7.7 Exams
- Exam fields: title, description, creatorId, schoolId, classId, duration (minutes), accessMode (`registered` | `open`), startTime/endTime/dueDate, questions[] (mcq/theory, options, correctOption, maxScore), isPublished, resultsPublished, resultPublishTime, linkToken (8-char).
- **Open access:** guests identified by candidateName/candidateEmail in `ExamSubmission` (studentId nullable).
- Exam-taking: `ExamSubmission` with status (`in-progress` → `submitted` → `graded`), timeRemaining, auto-submit, per-answer scores, totalScore.
- Results: `POST /api/exams/:id/publish-results` → scheduler `processPendingExamResults()` emails result links when public.
- Exam creator UI with AI question generation and LaTeX (KaTeX) rendering.

### 7.8 AI assistant (7 modes)
Providers: **Groq** (default, LLaMA 3.3 70B) or **Gemini**; selected via `Settings.activeAIProvider`; endpoints:
- `POST /api/ai/generate-classroom` → name/description/learningOutcomes
- `POST /api/ai/generate-topic` → topic with duration
- `POST /api/ai/generate-syllabus` → 5–10 ordered topics ("Import Syllabus")
- `POST /api/ai/generate-assignment` → MCQ/theory questions (count ≤ 20)
- `POST /api/ai/generate-exam` → timed exam (count ≤ 30, LaTeX-aware)
- `POST /api/ai/generate-powerpoint` + `POST /api/ai/download-powerpoint` → real `.pptx` with school/tutorial logo, speaker notes, themed slides
- `POST /api/ai/qna-assistant` → academic answer + follow-up suggestions
- `POST /api/ai/generate-marketing-email` + `generate-marketing-campaign` → drip email content
- All responses forced to JSON; errors logged without exposing secrets; students never see the panel.

### 7.9 Live lessons & collaboration
- **Zoom**: `POST /api/zoom/create-meeting/:classroomId` (JWT-based Zoom API), `GET /api/zoom/meeting/:classroomId`; CallSession records classroom/startedBy/link/startedAt/isPaid/amount.
- **Google Meet**: OAuth consent (`/api/google-auth/*`) storing `googleOAuthRefreshToken` for calendar/meet scopes; `GoogleMeetAuth` component.
- **Attendance**: `Attendance` per student per CallSession (unique index prevents duplicates).
- **Whiteboard**: Socket.io rooms keyed by classId; persisted strokes in `Whiteboard` model; virtual 10000×40000 canvas; teacher tools (width, undo, clear, night/dark mode, export PNG, **lock board**, selective user allow/unlock); student controls (follow teacher, raise hand); presence cursors/colors; real-time `wb:*` events.
- **WebRTC voice + video**: teacher-initiated voice (`wb:voice-start`), SDP offer/answer + ICE signaling, mute/unmute, **force-mute / mic-lock** (teacher), per-user mute/video state, voice-enabled gating.

### 7.10 Q&A board
- Boards tied to classroom (+optional topic), `shareableLink` token, `isPublic`, `allowAnonymous`, `hideQuestions`, `isActive`.
- Endpoints: create/list boards, post questions (students), answer, accept answer.
- Web: Q&A center `/qna/:token`, presentation mode `/qna/:token/present`. Mobile: Q&A center (WebView).

### 7.11 Payments, billing & disbursements
- **Stripe**: `POST /api/payments/checkout/:classroomId` (Checkout Session), signature-verified webhook, `POST /api/payments/:id/refund` (root admin).
- **Paystack**: initiate → inline widget → verify; webhook; guest checkout for public classes.
- Payment record: userId, type (`class_enrollment`, `topic_access`, `lecture_access`, `subscription`, `personal_teacher_subscription`), classroomId/topicId/callSessionId/planId, amount, currency, status, paystackReference/stripePaymentId, and financial breakdown: `taxAmount`, `vatAmount`, `serviceFeeAmount`, `payoutAmount` (computed from `Settings.taxRate/vatRate/serviceFeeRate`).
- **Disbursements**: root admin approves `POST /api/disbursements/approve/:paymentId` (generates `payoutReference`, sends `payout_received` notification + detailed email with fee breakdown); pending/history/my-payouts views; user bank details + payout frequency (daily/weekly/monthly) in Profile.
- **Subscriptions**: plans (trial/pay_as_you_go/weekly/monthly/yearly); `UserSubscription` (one per user), status lifecycle, `POST /api/user-subscriptions/issue-free-access` (root admin), trial = 14 days.

### 7.12 Notifications (3 channels)
- **In-app**: Notification model (userId, message, type, entityId/entityRef, read). Endpoints: list (latest 20), mark-read, mark-all-read, unread-count.
- **Email**: Brevo transactional (`utils/email.js`) + Nodemailer; templated wrapper.
- **Push**: Expo push via `User.expoPushToken`; Notification post-save hook triggers push.
- Notification types: `class_reminder`, `assignment_reminder`, `assignment_result`, `payment_success`, `payment_received`, `payout_received`, `new_assignment`, `new_submission`, `assignment_graded`, `subscription_success`, `student_enrolled`, `topic_activated`, `new_class_created`, `class_published`, `classroom_ended`, `marketing_job`.

### 7.13 Script sharing (external markers)
- `ScriptShareConfig` per exam/assignment: `isShareable`, `defaultAccessType` (view/grade), `otpLifespanMinutes`, `accessDurationMinutes`, `assignedMarkerId`.
- `ScriptAccessSession`: shareToken, submissionRef(s), groupName, requester info, **hashed OTP**, accessToken (time-limited), status (`pending_otp` → `active` → `saved`/`expired`), gradingSnapshot, savedSubmissions.
- Flow: teacher enables sharing → generates single or **group link** → external marker requests access (name/email) → authorities (creator, class teacher, school admins, assigned marker, root admins) receive OTP email → marker enters OTP → time-limited `view` or `grade` session → can save grading progress (`PATCH grade`) and **finalize** (`POST finalize`), which writes grades back to the real submission.
- Public page `/shared-script/:shareToken` on web.

### 7.14 Marketing engine
- Entities: MarketingList, MarketingContact (auto `unsubscribeToken`, timezone default Africa/Lagos), MarketingTemplate, MarketingCampaign (types: campaign_step/welcome/birthday/anniversary/referral/reactivation), MarketingJob, MarketingHoliday (month/day blackout), MarketingSendLog (dedupe indexes).
- CSV contact import (`POST /api/marketing/contacts/import-csv`, 10 MB), lists + add-contacts, templates + test send, campaigns create/start/pause, one-click unsubscribe.
- Scheduler processes up to 40 campaign-step emails/tick and 20 greeting recipients/tick; send logs + job analytics.
- AI can generate single emails and multi-step drip campaigns.

### 7.15 Reports & analytics
- Role-scoped reports: `GET /api/reports/student/me`, `/class/:classId`, `/all-students?schoolId=`, `/school/:schoolId`, `/admin/overview`.
- Web: per-role dashboards with student performance tables, grade distribution, enrollment, revenue; **CSV + PDF export** (jsPDF + autotable); school-switcher aware.
- Mobile: role-scoped Reports screen with PDF export.

### 7.16 Feedback
- `FeedbackRequest`: type (classroom/platform), status (pending/completed/dismissed), rating 1–5, comment; teacher/admin review surface `/feedbacks`.

### 7.17 Platform settings (root admin)
- taxRate, vatRate, serviceFeeRate, subjects[], `subscriptionCheckingEnabled`, `activeAIProvider`; managed at `/platform-settings`; subscription plans at `/subscription-plans-admin`.

### 7.18 Onboarding & platform UX
- Role-based OnboardingTour (spotlight masks) for first logins.
- Dark/light theme (web + mobile), school switcher, splash screen, error boundaries, loading/empty/error + retry states.

## 12. Non-functional requirements

### 12.1 Performance
- Paginate large classroom, user, payment, submission, notification lists; index classroom/school/user IDs, publication flags, payment references, timestamps.
- Mobile loads parallel classroom resources without blocking UI; API p95 < 500 ms for standard reads.
- Scheduler batch limits prevent bursts (e.g., 40 marketing emails/tick, 20 greeting recipients/tick).

### 12.2 Reliability
- Payment confirmation idempotent and replay-protected; publication actions idempotent.
- Scheduled jobs tolerate retries and partial failures; TTL + retry for push/email send paths.
- API errors recoverable with safe retry; mobile network-error + retry states.

### 12.3 Security & privacy
- Backend-enforced authorization; UI hiding is not a boundary.
- Ownership, school membership, class assignment, enrollment, publication validated server-side.
- bcrypt password hashing; OTPs/tokens expire (OTP 5-min 2FA, configurable script OTP, TTL access tokens); OTPs hashed before storage (script sharing).
- Rate-limit auth endpoints; internal endpoints gated by `x-internal-api-key`.
- Stripe webhook signature verified; Paystack callbacks verified server-side.
- Correct answers excluded from student responses before submission/result release.
- File uploads: mime/type + size limits (logo 2 MB, CSV 5–10 MB, topic videos 500 MB); Cloudinary sanitization with local fallback.
- Secrets only via env vars; security events logged without credentials/payment data; least privilege.
- Helmet, CORS allow-list, mongo-sanitize, express-validator, 50 MB JSON body limit.

### 12.4 Accessibility & usability
- Clear labels, contrast, touch targets, keyboard support, accessible roles.
- Dropdowns/toggles/selectors over ambiguous pills for single-value settings.
- Validation near field; input preserved on recoverable errors.
- Dark/light theme respected on web + mobile; no bright/flashy combinations; no white controls in dark mode.
- Forms touch-friendly; controlled inputs must not reset while typing (known bug class on mobile).

### 12.5 Observability
- Structured server errors; correlation/request IDs.
- Track auth, payment, publication, enrollment, notification, AI-provider, scheduler failures.
- Monitor API latency, job failures, websocket health, mobile crash reports.

## 13. Key user journeys

### 13.1 Teacher creates, publishes, and runs a class
1. Teacher signs in (passes verification + subscription gate).
2. Creates classroom (level, pricing, capacity, schedule, class format, public access window if public lecture/seminar).
3. Adds topics (manually or via AI syllabus import) and uploads videos.
4. Activates first topic → progression engine auto-advances.
5. Publishes and shares link (`/c/:shortCode`) → students discover/enroll/pay.
6. Launches live sessions (Zoom/Meet/whiteboard), tracks attendance, monitors progress.

### 13.2 Teacher creates an MCQ/theory assignment
1. Opens classroom assignment tab → create (manual or AI).
2. For MCQ: selects correct option via check icon; sets due date + result release.
3. Publishes → students notified → submit.
4. Grades MCQ automatically; theory manually or with AI marking; releases results.
5. Student receives result + can view score/feedback once released.

### 13.3 External marker grades scripts
1. Teacher enables script sharing on an exam/assignment and generates a single or group link.
2. Marker opens `/shared-script/:shareToken`, enters name/email.
3. Authority approves by sharing the OTP (sent to authority email).
4. Marker verifies OTP → time-limited session (view or grade).
5. Marker saves grading progress and finalizes → grades written back to the real submission.

### 13.4 Guest attends a public lecture
1. Student/guest opens public class page from catalog or link.
2. Chooses to join live or watch recording (within access window).
3. Pays via Paystack if required (guest checkout).
4. Records PublicAttendee; gets join instructions / recording link.
5. Host sees badges (Live Now / Recording / Window Closed) and attendee records.

### 13.5 Student completes a timed exam
1. Opens published exam via `/exam-center/:token` (registered or open).
2. App shows duration/window; starts attempt (in-progress persisted, timeRemaining).
3. Answers MCQ + theory (LaTeX supported); auto-submit at timeout.
4. Results released per config → email + in-app.

### 13.6 Teacher monetizes and gets paid
1. Sets pricing (per_lecture/per_topic/weekly/monthly/one_time/free).
2. Student pays via Paystack/Stripe → verified → enrolled → payment record with fee breakdown.
3. Payout amount accrues; root admin approves disbursement → payout email + reference.
4. Teacher configures bank details + payout frequency in Profile.

### 13.7 Teacher grows with marketing
1. Builds contacts (manual/CSV) and lists.
2. Creates templates and multi-step campaigns (or AI-generates them).
3. Launches → scheduler sends with holiday blackouts, dedupe, unsubscribe links.
4. Reviews send logs and job analytics.

## 17. Acceptance criteria (release gate)

- All roles see and can perform only permitted actions; verified end-to-end (API + UI).
- Unverified and pending-onboarding users routed correctly; 2FA enforced for root admin.
- Students never see unpublished classes, assignments, or exams; correct answers never leak pre-release.
- Payments record reference, payer, purpose, class/topic/subscription, fee breakdown, and date; enrollment only after verified payment.
- Script sessions expire; OTPs hashed; grades finalize correctly back to submissions.
- Public classes show correct Live/Recording/Closed state and gate guest access correctly.
- Light and dark themes readable on all surfaces; mobile deep links restore correct screen.
- Uploads, notifications, payment webhooks, and scheduled jobs tested in staging.
- API errors, loading states, empty states, retry flows present on web and mobile.

## 18. Risks & mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Payment webhook/verification failures lose enrollments | High | Idempotent confirmation, webhook retries, signature verification, monitoring |
| AI provider cost/errors | Medium | Draft-first UX, provider switch, JSON validation, error logging |
| Mobile/web behavior drift | Medium | Parity checklist per milestone; shared role/theme/API utilities |
| Cron misfires over-promote topics | Medium | Idempotent jobs, retries, manual set-next/reset |
| Subscription gate locks paying users | Medium | Global kill-switch (`subscriptionCheckingEnabled`) |
| Script-sharing OTP phishing/social engineering | Medium | Authority-only OTP emails, short lifespan, hashed OTPs, session TTL |
| Answer leakage in exams/assignments | High | Server-side field stripping before release; tests |
| Guest public-class abuse (spam attendance) | Medium | Rate limiting on public endpoints, attendee records |
| 2FA lockout (root admin) | Medium | Backup codes, temp login token |
